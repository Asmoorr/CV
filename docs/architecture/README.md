# Архитектура

## Обзор

Приложение построено на Next.js 16 с App Router и React 19. Страницы формируются из типизированных данных резюме, а компоненты отвечают только за отображение и поведение интерфейса. Такое разделение позволяет обновлять содержание независимо от разметки.

Основные части проекта:

```text
src/
├── app/                 Маршруты, корневая разметка, метаданные и стили
│   ├── [locale]/        Страница резюме для выбранного языка
│   ├── layout.tsx       Общая HTML-разметка и локальный шрифт
│   ├── page.tsx         Перенаправление с / на /ru
│   └── globals.css      Глобальные стили и адаптивное оформление
├── components/          Переиспользуемые части интерфейса
│   ├── sections/        Секции резюме
│   └── ui/              Небольшие UI-компоненты
├── content/             Данные русской и английской версий
│   └── schema.ts        Общие TypeScript-типы контента
├── fonts/               Локальные файлы Manrope
└── proxy.ts             Выбор языка запроса и перенаправление
tests/                   Модульные и визуальные проверки
public/                  Статические общедоступные файлы
```

## Маршрутизация и язык

Основной маршрут находится в `src/app/[locale]/page.tsx`. Функция `generateStaticParams` объявляет две поддерживаемые локали: `ru` и `en`. Неизвестное значение языка приводит к странице 404.

Запрос к `/` перенаправляется на `/ru`. Файл `src/proxy.ts` также определяет язык по пути и передаёт его в заголовке `x-resume-locale`. Корневой layout читает этот заголовок и устанавливает корректный атрибут `lang` у элемента `<html>`.

Переключатель языка сохраняет оставшуюся часть пути и якорь текущей секции. Например, переход с `/ru#projects` ведёт на `/en#projects`.

## Формирование страницы

Для выбранной локали страница получает единый объект `ResumeContent` из `src/content`. Затем его части передаются соответствующим секциям:

1. `Header` — навигация и выбор языка.
2. `Hero` — вводный экран.
3. `About` — общая информация.
4. `Timeline` — опыт и хронология.
5. `Projects` — проекты.
6. `Skills` — навыки.
7. `Contact` — контакты.
8. `Footer` — нижняя часть страницы.

Метаданные страницы также создаются из локализованного контента: имя и роль формируют заголовок, а краткое описание используется как description.

## Серверные и клиентские компоненты

Страница и большинство секций рендерятся на сервере. Клиентскими оставлены только компоненты, которым нужен браузерный API или локальное состояние:

- `Header` управляет мобильным меню, текущим путём и переключением языка;
- `FinePointerCursor` отслеживает указатель мыши и включается только на устройствах с точным курсором;
- `HeroField` рисует декоративное поле на canvas, реагирует на размер окна и учитывает настройку уменьшенного движения.

Это сокращает объём клиентского JavaScript и сохраняет основное содержимое доступным без выполнения интерактивного кода.

## Сборка

В `next.config.ts` включён режим `output: "standalone"`. Production-сборка содержит минимальный сервер и необходимые зависимости, поэтому подходит как для прямого запуска Node.js, так и для Docker-образа. Заголовок `X-Powered-By` отключён, строгий режим React включён.

## Принципы изменений

- Биографические данные хранятся в `src/content`, а не в JSX.
- Обе локали соответствуют общей схеме `ResumeContent`.
- Новая секция получает отдельный тип данных и компонент отображения.
- Поведение, зависящее от браузера, изолируется в клиентском компоненте.
- Изменения разметки и стилей проверяются визуальными тестами на всех поддерживаемых разрешениях.
