## Why

Приложение имеет понятное разделение контента и представления, но несколько инфраструктурных решений создают лишнюю связанность: локаль передаётся в root layout через request header, список языков повторяется в нескольких слоях, все стили сосредоточены в глобальном файле, а декоративные клиентские компоненты используют недетерминированную или постоянно работающую анимацию. Перед следующими визуальными изменениями эти границы нужно упростить, сохранив текущий интерфейс как неизменяемый контракт.

## What Changes

- Разделить CSS на глобальный фундамент и локальные стили компонентов: в глобальной области оставить reset, дизайн-токены, базовую типографику и общие layout-примитивы, а стили секций и интерактивных компонентов разместить рядом с их владельцами.
- Перевести компонентные стили на CSS Modules, устранив зависимость JSX от глобальных имён классов и сохранив глобальные классы только там, где они действительно образуют общий публичный примитив.
- Систематизировать дизайн-токены для цвета, размеров контейнера, интервалов, слоёв, границ и motion, исключив повторяющиеся магические значения там, где они выражают одну роль.
- Организовать responsive-правила по компонентам, чтобы базовая разметка и её breakpoint-варианты изменялись совместно.
- Явно разделить структурные стили, визуальные состояния и progressive enhancement для `Header`, `HeroField` и `FinePointerCursor`.
- Перенести locale-aware root layout в сегмент `app/[locale]`, получать локаль напрямую из route params и убрать зависимость документа от request header.
- Свести поддерживаемые языки, их проверку, static params и данные переключателя к единому locale registry вместо повторения `ru`/`en` в маршрутизации и компонентах.
- Пересмотреть необходимость `proxy`: оставить его только при наличии самостоятельной ответственности за перенаправление либо заменить корневым route redirect без промежуточного заголовка.
- Сделать начальное состояние `HeroField` детерминированным, а циклы `requestAnimationFrame` в декоративных компонентах — активными только тогда, когда требуется видимое движение.
- Проверить границы Server и Client Components: статические секции и маршрутизация остаются серверными, а клиентский bundle содержит только минимальные интерактивные острова.
- Сохранить текущие маршруты, контентную модель, DOM-семантику, внешний вид на поддерживаемых разрешениях и клиентское поведение.
- Не изменять существующие unit- и visual-тесты и не обновлять эталонные снимки: они используются как неизменяемый контракт рефакторинга.

## Capabilities

### New Capabilities

Нет: изменение не добавляет пользовательского поведения.

### Modified Capabilities

Нет: это внутренний рефакторинг без изменения требований; change использует `skip_specs: true`.

## Impact

- Будут затронуты структура `src/app`, `src/proxy.ts`, locale exports в `src/content`, `src/app/globals.css`, компоненты в `src/components` и новые файлы стилей рядом с компонентами.
- Возможна небольшая корректировка JSX только для подключения CSS Modules и общих примитивов; содержание и семантическая структура страницы остаются прежними.
- Новые runtime-зависимости, API, публичные маршруты и изменения содержимого резюме не требуются.
- `tests/content.test.ts`, `tests/visual`, Playwright-конфигурация и текущие PNG-эталоны остаются без изменений.
