# Spec Delta

## REMOVED Requirements

### Requirement: Контактная секция предоставляет frontend-only форму
Система SHALL предоставить локализованную форму с полями имени, обратного email и сообщения, действием отправки и сохранёнными прямыми контактными ссылками. Поле сообщения SHALL быть главным визуальным элементом секции и использовать текущие цвета сайта и шрифт с поддержкой кириллицы и латиницы. Текущая версия MUST NOT отправлять сетевой запрос и MUST честно сообщать, что доставка сообщения будет добавлена позже.

#### Scenario: Допустимые данные
- **WHEN** пользователь вводит допустимые имя, email и сообщение и активирует действие отправки
- **THEN** система не выполняет сетевой запрос, сохраняет введённые значения и показывает локализованное уведомление о том, что отправка пока недоступна

#### Scenario: Ошибка проверки
- **WHEN** обязательное поле пусто, email имеет неверный формат или сообщение превышает допустимый размер
- **THEN** система связывает локализованное сообщение об ошибке с соответствующим полем и не переходит к уведомлению о недоступной отправке

#### Scenario: Прямой контакт остаётся доступен
- **WHEN** пользователь хочет отправить сообщение немедленно
- **THEN** секция предлагает рабочую прямую email-ссылку как альтернативу ещё не подключённой форме

#### Scenario: Контроль отсутствия передачи
- **WHEN** пользователь взаимодействует с frontend-only формой
- **THEN** значения полей не передаются серверу, внешнему сервису или аналитическому endpoint

**Reason**: Форма должна доставлять сообщения через серверную интеграцию с Telegram Bot API вместо локального состояния «доставка не подключена».

**Migration**: Использовать новый API-контракт ниже; сохранить прямую email-ссылку как альтернативу при недоступности сервиса.

## ADDED Requirements

### Requirement: Контактная форма передаёт сообщение в настроенный Telegram-чат
Система SHALL предоставлять публичный endpoint `POST /api/contact` для существующей формы. Endpoint SHALL принимать JSON с непустыми строковыми полями `name`, `email` и `message`; удалять внешние пробелы перед проверкой; проверять email и длины полей на сервере. Имя SHALL содержать не более 120 символов Unicode, email — не более 254 символов, сообщение — не более 1500 символов Unicode, а тело запроса — не более 16 KiB. В сообщении SHALL сохраняться переносы строк. Поля SHALL отправляться обычным текстом без интерпретации HTML или Markdown.

Endpoint SHALL отправлять проверенные данные только в один целевой чат, заданный серверной конфигурацией. Успешный ответ `200` с `{ "ok": true }` SHALL возвращаться только после подтверждения успешной доставки Telegram Bot API. Система MUST NOT сохранять сообщение в постоянное хранилище или журналировать текст, имя, email, токен бота либо полный URL запроса к Telegram.

#### Scenario: Сообщение доставлено
- **WHEN** запрос содержит допустимые поля и Telegram Bot API подтверждает отправку
- **THEN** endpoint возвращает `200` и `{ "ok": true }`, а в настроенном чате появляется одно сообщение с именем, обратным email и текстом пользователя

#### Scenario: Некорректный ввод
- **WHEN** JSON невалиден, обязательное поле отсутствует или пусто, email некорректен либо нарушено ограничение длины
- **THEN** endpoint возвращает `400` с безопасным кодом ошибки, не вызывает Telegram Bot API и не включает введённые персональные данные в ответ

#### Scenario: Неподдерживаемый тип или слишком большое тело
- **WHEN** Content-Type не является `application/json` либо тело запроса превышает 16 KiB
- **THEN** endpoint возвращает соответственно `415` или `413` и не вызывает Telegram Bot API

#### Scenario: Доставка не удалась
- **WHEN** Telegram Bot API отклоняет отправку, недоступен или не отвечает в установленный тайм-аут
- **THEN** endpoint возвращает `502` с общим кодом ошибки доставки, не раскрывает ответ Telegram или секреты и не сообщает об успехе

#### Scenario: Серверная конфигурация отсутствует
- **WHEN** токен бота или ID целевого чата не настроен на сервере
- **THEN** endpoint возвращает `503` с общим кодом временной недоступности и не вызывает Telegram Bot API

#### Scenario: Превышен лимит отправок
- **WHEN** запрос блокируется настроенным лимитом частоты для endpoint
- **THEN** endpoint возвращает `429`, не вызывает Telegram Bot API и при возможности указывает время до следующей попытки через `Retry-After`

#### Scenario: Секреты и персональные данные остаются закрытыми
- **WHEN** endpoint обрабатывает запрос или возвращает любой результат
- **THEN** токен Telegram доступен только серверному коду, а ответ и журналы содержат лишь технический статус/код ошибки без текста формы, email, токена и URL с токеном
