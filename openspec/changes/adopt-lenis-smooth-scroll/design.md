# Design

## Context

Приложение работает на Next.js 16.3.5 и React 19.3.0 с App Router. `[locale]/layout.tsx` рендерит `LocaleTransitionProvider`, внутри которого `EntryExperience` оборачивает страницу. Входная заставка задаёт `data-entry-state` и блокирует overflow документа до завершения входа; после перехода к состояниям `entered` или `bypassed` основной контент становится интерактивным. Страница использует document scroll, а мобильная панель Header имеет собственный `overflow-y: auto` и при открытии блокирует прокрутку body.

`SmoothWheelScroll` сейчас подключён из page-компонента и вручную интерполирует `window.scrollY`. `LocaleTransition` сбрасывает страницу наверх перед навигацией, `EntryExperience` делает то же при входе, а `BackToTop` сначала отправляет `smooth-scroll:reset`, затем отдельно просит браузер плавно прокрутить страницу. Следовательно, это событие сейчас означает синхронизацию контроллера, а не команду прокрутить наверх. Общие стили задают `scroll-behavior: smooth` и `scroll-padding-top: 88px`.

См. [proposal.md](proposal.md) для мотивации и [specs/site-interactions/spec.md](specs/site-interactions/spec.md) для поведенческих требований. Lenis выбран как узкий scroll engine: текущему сайту не нужны scroll-trigger orchestration, сложные parallax-сцены или отдельная animation-экосистема. Официальный `lenis/react` предоставляет root-интеграцию и `useLenis`; core предоставляет `scrollTo`, `start`/`stop`, anchor-навигацию и поддержку reduced-motion.

## Goals / Non-Goals

**Goals:**

- Поддерживать ровно один JavaScript-слой для сглаживания wheel-ввода страницы.
- Сохранить viewport/document scroll, нативную полосу прокрутки и нативное touch-поведение.
- Оставить страницу неподвижной, пока входной слой блокирует основной контент; разблокировать её после завершения входа или безопасного пропуска заставки.
- Направлять fragment-ссылки и программные переходы через общий Lenis-инстанс.
- Сохранить разные режимы программной прокрутки: плавный для `BackToTop`, мгновенный для входа и смены локали.
- Учитывать reduced-motion, pinch-to-zoom, горизонтальные жесты и собственную прокрутку мобильной панели.
- Удалить ручной wheel-loop, его внутренние data-state и событие, когда все потребители переведены на общий API.

**Non-Goals:**

- Parallax, scroll-linked effects, scroll snapping, перелистывание по секциям и горизонтальный scroll.
- Перенос reveal-анимаций, курсора или locale transition на Lenis scroll events.
- Замена `IntersectionObserver`, добавление GSAP/Motion/Locomotive Scroll или перестройка страницы в transform-wrapper.
- Изменение визуального дизайна входной заставки, Header, Footer или содержания RU/EN.

## Decisions

### 1. Постоянный root-инстанс в locale layout

Разместить клиентскую root-интеграцию Lenis в `src/app/[locale]/layout.tsx`, рядом с существующей инфраструктурой провайдеров. Инстанс должен использовать viewport как scroll container и переживать обновление содержимого страницы внутри layout. Компоненты, которым нужны программные действия, используют публичный `useLenis` из `lenis/react`; не создают локальные экземпляры.

Включить автоматический RAF Lenis. Не добавлять собственный wheel-listener, второй RAF-loop или ручной `window.scrollTo` для эффектов, управляемых Lenis. Базово обрабатывать wheel, оставить `syncTouch` выключенным и `wheelMultiplier` равным единице; сглаживание настраивать публичными параметрами Lenis с сохранением пропорциональности небольших trackpad delta.

Отдельный экземпляр внутри page-компонента отклонён: он может пересоздаваться при навигации и не даёт единой точки управления для заставки и Footer.

### 2. Согласовать lifecycle с входной заставкой

Поскольку `EntryExperience` устанавливает `data-entry-state` до разблокировки документа, Lenis должен быть остановлен в состояниях `loading`, `ready` и `opening`. После перехода в `entered` или `bypassed` он запускается, а стандартный overflow-lock заставки снимается. При начальной загрузке с уже пройденной заставкой engine не должен оставаться остановленным.

Синхронизировать lifecycle по фазам `EntryExperience` либо по одному явному событию состояния; не полагаться только на CSS `overflow:hidden`, потому что Lenis отдельно обрабатывает wheel-события. Нативное touch-поведение и фокус кнопки входа остаются под контролем браузера.

### 3. Фильтровать неподдерживаемый wheel-ввод средствами Lenis

Не перехватывать wheel вне Lenis. Использовать его публичные опции:

- `virtualScroll` пропускает pinch-to-zoom (`ctrlKey`) и горизонтально доминирующие жесты;
- `prevent` или `data-lenis-prevent` передаёт ввод вложенным scroll-областям;
- `syncTouch: false` оставляет touch-прокрутку браузеру и избегает экспериментальной touch-инерции.

Открытая мобильная панель Header получает маркер nested-scroll только пока она открыта. Её текущие `overflow-y: auto`, блокировка фона и `overscroll-behavior: contain` сохраняются. Не включать глобальную автоматическую проверку всех вложенных контейнеров без необходимости.

### 4. Использовать `useLenis` для разных программных сценариев

Удалить событие `smooth-scroll:reset`: оно сейчас только сбрасывает внутренние координаты старого контроллера, а не прокручивает страницу. Команды выполняются непосредственно через общий API:

- `EntryExperience` перед началом раскрытия сбрасывает позицию наверх немедленно и сохраняет блокировку до перехода в `entered`;
- `LocaleTransition` останавливает остаточную инерцию, переводит текущую страницу наверх немедленно и после навигации оставляет новую локаль у начала;
- `BackToTop` выполняет плавный переход к началу, при reduced-motion — немедленный; сохраняет запись `#top` в URL и последующий перенос фокуса на `#main` без прокрутки;
- fragment-ссылки Header и skip-link используют anchor-механизм Lenis и сохраняют семантическую навигацию.

Одинаковое reset-событие с интерпретацией «прокрутить наверх» отклонено: это сломало бы плавный `BackToTop` и смешало бы команду отмены остаточного движения с командой навигации.

### 5. Согласовать anchor offset и глобальный CSS

Включить anchor-навигацию Lenis. Сохранить `scroll-padding-top: 88px` как no-JavaScript fallback, но задать активную коррекцию фиксированной шапки только один раз. Конкретное место коррекции определить при интеграции по реальному поведению Lenis; проверить позицию целевого заголовка в браузере и отсутствие двойного смещения.

Клавиатурный фокус skip-link и `BackToTop` остаётся самостоятельным от прокрутки. `prefers-reduced-motion` отключает smoothing wheel-ввода и делает программную прокрутку мгновенной; при этом `focus({ preventScroll: true })` не должен запускать дополнительное движение.

### 6. Удалить устаревший DOM-контракт и проверять наблюдаемое поведение

Подключить официальный CSS Lenis в глобальном стиле и сверить его с текущим `scroll-behavior`, `scroll-padding-top` и reduced-motion правилами. После переноса всех потребителей удалить `.is-wheel-scrolling`, `data-smooth-scroll*`, `smooth-scroll:reset` и старый `SmoothWheelScroll`.

Playwright проверяет фактическую позицию и динамику прокрутки, завершение движения, поведение anchors, overlay, меню и locale transition. Если нужен тест наличия интеграции, использовать публичный API или отдельную тестовую точку адаптера, а не приватные поля экземпляра и CSS-классы как продуктовый контракт.

## Risks / Trade-offs

- **[Risk]** Входной overlay использует `overflow:hidden`, но Lenis всё ещё может принять wheel-ввод до запуска страницы. → **Mitigation:** явно останавливать engine до `entered`/`bypassed` и проверять загрузку как с новой сессией, так и с уже пройденной заставкой.
- **[Risk]** Переходы, заданные через разные API, могут дать двойное движение или устаревшую целевую позицию. → **Mitigation:** все программные команды вести через общий `useLenis`, разделить immediate и smooth сценарии и покрыть каждый browser-тестом.
- **[Risk]** CSS `scroll-padding-top` и anchor offset Lenis могут сдвинуть цель дважды. → **Mitigation:** оставить только одну активную коррекцию в runtime и измерять фактическое положение заголовка относительно Header.
- **[Risk]** Nested-scroll маркер на закрытом или слишком широком элементе может поглотить ввод документа. → **Mitigation:** выставлять его только на открытой мобильной панели и проверять прокрутку внутри/снаружи.
- **[Risk]** Lenis иначе сгладит небольшие trackpad delta, чем текущий адаптивный коэффициент. → **Mitigation:** не усиливать delta, оставить множитель равным единице и настроить только публичные параметры сглаживания.
- **[Risk]** Browser tests, ожидающие внутренние data-state, перестанут отражать поведение пользователя. → **Mitigation:** переписать ожидания на фактические scroll-позиции и стабилизацию документа.

## Migration Plan

Миграция данных не требуется. Добавить зависимость и root-интеграцию; связать lifecycle заставки, мобильную панель и программные команды; обновить браузерные сценарии; затем удалить старый контроллер и его DOM-контракт. Для отката восстановить `SmoothWheelScroll`, прежние CSS-правила и вызывавшие reset-событие команды, удалив зависимость Lenis; маршруты и контент не затрагиваются.
