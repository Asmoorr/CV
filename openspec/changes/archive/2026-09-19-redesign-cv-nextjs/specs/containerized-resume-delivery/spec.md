## Purpose

Определяет воспроизводимую production-сборку сайта-резюме в Docker, чтобы одно и то же приложение предсказуемо запускалось локально и на сервере без среды разработки.

## ADDED Requirements

### Requirement: Production-образ
Проект SHALL предоставлять Docker-образ, который собирает оптимизированную production-версию сайта и запускает её непривилегированным пользователем.

#### Scenario: Сборка образа
- **WHEN** пользователь выполняет документированную команду `docker build`
- **THEN** сборка завершается без зависимости от локально установленных пакетов проекта

### Requirement: Запуск контейнера
Контейнер SHALL принимать порт через стандартную конфигурацию запуска и SHALL обслуживать сайт после старта без дополнительных ручных команд.

#### Scenario: Локальный запуск
- **WHEN** пользователь запускает собранный образ с опубликованным портом 3000
- **THEN** главная страница доступна через HTTP на указанном порту

### Requirement: Минимальный runtime-контекст
Production-слой SHALL исключать исходные инструменты разработки, локальные кэши, `.git`, OpenSpec-артефакты и прочие файлы, не нужные для выполнения приложения.

#### Scenario: Проверка контекста сборки
- **WHEN** Docker формирует контекст и runtime-слой
- **THEN** исключённые файлы не копируются в финальный образ

### Requirement: Документированный запуск
Репозиторий SHALL содержать короткие проверяемые инструкции для запуска в режиме разработки, production-сборки и Docker-контейнера.

#### Scenario: Новый разработчик запускает проект
- **WHEN** разработчик следует README на машине с поддерживаемыми Node.js и Docker
- **THEN** он может открыть сайт без поиска дополнительных неописанных шагов
