# Design

## Context

Страница собирается в App Router из server-компонентов, а браузерное поведение вынесено в небольшие client-компоненты. Основной документ уже содержит Hero, `Footer`, локализованный контент и существующие scroll/reveal-механизмы; новые требования описаны в `staged-site-entry` и `scroll-guidance-and-reveal`. Референс Carl Gordon Media используется только для тёмной минималистичной композиции, контурной кнопки, кругового маркера и ощущения «входа» в опыт.

## Goals / Non-Goals

**Goals:**

- Показать entry-overlay на самом раннем безопасном кадре и не задерживать его появление загрузкой основного сайта.
- Сохранить серверный HTML основного сайта и дать ему загружаться за overlay.
- Сделать один управляемый переход `ENTER → Hero`, доступный мышью, касанием и клавиатурой.
- Ограничить флаг текущей вкладкой через `sessionStorage`, добавить fail-open поведение и локализованный reset в footer.
- Не создавать горизонтальный overflow, дополнительную scroll-инерцию, звук или внешние зависимости.

**Non-Goals:**

- Переписывать существующий `SmoothWheelScroll`, локализацию маршрутов, SEO или структуру секций.
- Загружать внешний видео/аудио/шрифтовый ассет ради референса.
- Делать overlay постоянным модальным окном, хранить прохождение в `localStorage` или показывать его между вкладками.
- Перезапускать overlay сразу после клика reset в footer поверх текущего scroll-положения; reset только очищает флаг для следующего открытия/перезагрузки.

## Decisions

### Ранний fail-open gate без серверного чтения sessionStorage

Добавить маленький inline bootstrap-скрипт в locale layout перед интерактивным содержимым. Он пытается прочитать namespaced-ключ вроде `cv:entry-seen:v1` и выставляет на `html` только data-атрибут состояния: `required` при отсутствии флага или `bypassed` при наличии/ошибке storage. CSS по умолчанию скрывает overlay и оставляет сайт доступным, поэтому без JavaScript сайт не блокируется; при `required` overlay становится видимым ещё до гидрации.

Это выбрано вместо client-only проверки в `useEffect`, потому что она допускает flash основного сайта до решения. Это также безопаснее, чем серверная cookie-проверка: cookie не нужна, а session-флаг остаётся scoped to tab. Ошибка чтения/записи считается fail-open, чтобы приватный режим или строгая политика браузера не превращались в блокирующий экран.

### Overlay и сайт остаются в одном серверном документе

Рендерить entry-overlay рядом с page shell, а не динамически подменять весь сайт. Main/header/footer остаются в HTML и могут гидратироваться/загружать ресурсы за overlay; при `required` runtime применяет `inert`, `aria-hidden`/pointer guard и `overflow: hidden` к shell. После подтверждения сначала переводится состояние в `opening`, затем guard снимается только после transition-end или короткого fallback timeout.

Это сохраняет SEO и сценарий без JavaScript и не создаёт конкурирующий механизм загрузки страницы. Dynamic import основного сайта не нужен: пользователь просит догрузку за overlay, а не удаление server-rendered контента.

### Состояния и motion-связка

Использовать конечные состояния `bypassed`, `loading`, `ready`, `opening`, `entered` и `error-open`. Overlay получает локализованные строки из контента. `loading` длится только пока проверяются критичные шрифты/начальный Hero; короткий защитный timeout разрешает вход без искусственного ожидания.

Кнопка `ENTER` строится из фиксированной геометрии и CSS custom properties: её outline, круговой marker и accent меняют состояние через один `data-entry-phase`. Во время `opening` outline расширяется в круговой ореол, overlay уходит через opacity/clip-path, а Hero принимает тот же phase и раскрывает контент по staggered opacity/translate. Размеры layout не меняются; переход завершается через `transitionend` с таймаутом. При reduced motion phase меняется без масштабного перемещения, а focus management и порядок состояний остаются теми же.

Альтернатива — View Transitions API — не выбрана: он не гарантирован во всех поддерживаемых браузерах и не нужен для этой локальной связки. Анимация остаётся на CSS с JS-оркестрацией только состояний.

### Session reset в footer

Расширить тип footer-контента локализованными label/success/error строками и передать их в небольшой client-контрол. Кнопка вызывает `sessionStorage.removeItem` только для namespaced entry-ключа, обновляет live-region и оставляет страницу на текущем месте. Она визуально вторична относительно подписи footer, но имеет полноценный text label, keyboard target и `focus-visible`.

### Фокус и деградация

При активации overlay фокус переводится на `ENTER`; underlying shell не участвует в tab order. После завершения входа фокус переводится на `main` или первый осмысленный Hero-heading с `preventScroll`, чтобы не изменять scroll-позицию. При сбое storage/JS overlay не должен удерживать пользователя; при reduced motion переход завершается коротким состоянием opacity.

## Risks / Trade-offs

- [Inline gate может быть удалён/заблокирован политикой CSP] → Сохранить fail-open CSS-default и проверить production HTML; при невозможности inline script основное содержимое остаётся доступным.
- [Пользователь увидит недогруженную страницу после раннего ENTER] → Ограничить готовность критичных ресурсов шрифтами и Hero, использовать короткий cap timeout и не ждать второстепенные секции.
- [Transition может не прислать `transitionend`] → Добавить idempotent fallback timeout, который завершает `opening` и разблокирует shell.
- [Overlay или reveal вызовут дополнительную scroll-инерцию] → Не перехватывать wheel/touch, снимать lock до начала обычной прокрутки и проверить существующие `data-smooth-scroll-*` состояния.
- [Footer reset создаст ложное ожидание немедленного повторного overlay] → Явно сообщать, что флаг очищен для следующего открытия/перезагрузки; не менять текущую страницу внезапно.
- [Референс будет воспринят как копирование] → Ограничить решение общей композицией и motion-идеей, использовать текущие токены `carbon/paper/signal/rule`, существующий Manrope и собственную геометрию.

## Migration Plan

Изменение аддитивное: новый ключ не затрагивает прежние session-данные, а отсутствие ключа трактуется как первый вход. После внедрения проверить production build, обе локали и визуальные snapshots; rollback удаляет gate/контролы без миграции данных. Если версия motion не готова, функциональный overlay можно временно оставить с reduced-motion-переходом, не меняя контракт sessionStorage.
