## Purpose

Обеспечить воспроизводимую и наглядную проверку итогового вида локализованного приложения на ключевых разрешениях после изменений кода.

## ADDED Requirements

### Requirement: Матрица локалей и разрешений
Система визуального тестирования SHALL сравнивать полную страницу каждой поддерживаемой локали с версионируемым эталоном на desktop 1440×1000, tablet 768×1024 и mobile 320×800 при device scale factor 1.

#### Scenario: Полная проверка адаптивного вида
- **WHEN** разработчик запускает визуальные тесты
- **THEN** система проверяет `/ru` и `/en` на каждом из трёх заданных viewport
- **AND** для каждой комбинации сравнивает полноэкранный снимок с отдельным эталоном

### Requirement: Воспроизводимый снимок
Система визуального тестирования SHALL снимать страницу только после её готовности и загрузки шрифтов, SHALL запрашивать reduced motion и SHALL исключать нестабильные эффекты указателя и анимаций из результата.

#### Scenario: Повторный прогон без изменения приложения
- **WHEN** визуальный тест повторно выполняется в одинаковом поддерживаемом окружении без изменения приложения или эталонов
- **THEN** полученные снимки проходят сравнение с эталонами

### Requirement: Наглядный результат расхождения
При несовпадении снимка с эталоном система SHALL завершать проверку ошибкой и SHALL сохранять эталонное, фактическое и diff-изображение в невключаемых в Git артефактах, доступных через локальный HTML-отчёт.

#### Scenario: Обнаружено визуальное изменение
- **WHEN** итоговый вид хотя бы одной проверяемой комбинации отличается от эталона сильнее настроенного допуска
- **THEN** проверка завершается ошибкой
- **AND** отчёт показывает соответствующие expected, actual и diff-изображения с именем локали и viewport

#### Scenario: Визуальных изменений нет
- **WHEN** все снимки совпадают со своими эталонами в пределах настроенного допуска
- **THEN** проверка завершается успешно
- **AND** не требует изменения эталонов

### Requirement: Управляемое принятие нового вида
Система SHALL предоставлять отдельную явную команду обновления эталонных изображений и SHALL хранить обновлённые эталоны в системе контроля версий для ревью вместе с изменением кода.

#### Scenario: Намеренное обновление дизайна
- **WHEN** разработчик проверил визуальные различия и запускает команду обновления эталонов
- **THEN** система заменяет только эталоны проверяемой матрицы актуальными снимками
- **AND** изменения PNG доступны в Git diff для осознанного принятия

#### Scenario: Обычный тестовый прогон
- **WHEN** разработчик запускает обычную команду визуальной проверки
- **THEN** система не изменяет версионируемые эталоны

### Requirement: Разделение быстрых и браузерных проверок
Система SHALL сохранять существующий набор unit-тестов как быструю отдельную проверку и SHALL предоставлять визуальные тесты отдельной командой.

#### Scenario: Проверка контента без браузера
- **WHEN** разработчик запускает существующую команду unit-тестов
- **THEN** тесты структуры контента выполняются без запуска визуальной матрицы
