## Context

Страница сейчас задает `scroll-behavior: smooth`, но это сглаживает программные и якорные переходы, а не последовательность wheel-событий от колеса мыши или тачпада. Кастомный курсор включается только для fine-pointer устройств и перемещает кольцо через `requestAnimationFrame`. Переключатель языка строит новый pathname, но при клике дописывает текущий hash; если пользователь после перехода к секции вручную вернулся наверх, этот устаревший hash на новой локали снова прокручивает страницу к секции. См. требования в `specs/site-interactions/spec.md`.

## Goals / Non-Goals

**Goals:**

- Добавить компактное управляемое сглаживание wheel-прокрутки без тяжелого runtime и без привязки к секциям.
- Сделать управление тачпадом точным: мелкие жесты остаются мелкими, а смена направления ощущается немедленной.
- Добавить одно визуальное hover-состояние в существующий курсор без влияния на layout и обработку кликов.
- Сохранить отдельный выразительный hover-отклик навигации без увеличения кольца курсора.
- Сделать смену языка детерминированной: новая локаль всегда начинает отображение сверху.
- Покрыть регрессии браузерными проверками поведения, а не только снимками страницы.

**Non-Goals:**

- Scroll snapping, покадровое перемещение по секциям и искусственная фиксированная длительность каждого жеста.
- Горизонтальная прокрутка, pinch-to-zoom и вложенные области прокрутки, которые могут обработать ввод самостоятельно.
- Анимация элементов навигации, мобильного меню и переключателя языка через увеличение курсора.
- Сохранение позиции или активной секции между локалями.
- Изменение контента, маршрутов локалей или визуального дизайна самих ссылок.

## Decisions

### Сглаживать wheel-ввод через одну целевую позицию и один animation-frame цикл

Реализовать небольшой клиентский контроллер прокрутки без привязки к React-render циклу. Он хранит фактическую и целевую вертикальные позиции, добавляет нормализованный `deltaY` к цели, ограничивает цель диапазоном документа и в единственном `requestAnimationFrame` приближает фактическую позицию к цели через ограниченную интерполяцию. Цикл останавливается при достаточно малой разнице, чтобы не расходовать кадры в покое.

Обработчик wheel должен:

1. Игнорировать pinch-to-zoom (`ctrlKey`), горизонтально доминирующие жесты и события из вложенного прокручиваемого контейнера, который еще может двигаться в требуемом направлении.
2. Нормализовать `deltaMode` в пиксели, но не умножать пиксельные значения тачпада агрессивным коэффициентом.
3. Перед новым жестом синхронизировать базовую позицию с фактическим `scrollY`, если страницу переместили клавиатурой, якорем, браузерной историей или программно.
4. Добавлять ввод к одной целевой позиции, ограниченной диапазоном `0…scrollHeight - innerHeight`, и не накапливать смещение за границами документа.
5. При смене знака `deltaY` сокращать либо сбрасывать остаток предыдущей инерции, чтобы обратный жест сразу менял направление.
6. Использовать небольшое адаптивное сглаживание: колесо получает мягкое объединение дискретных импульсов, а частые малые события тачпада следуют за пальцами ближе к нативному движению.

Нативный `scroll-behavior: smooth` не должен одновременно сглаживать каждый программный кадр контроллера, иначе возникает двойная задержка; для управляемого wheel-пути следует использовать мгновенное позиционирование между кадрами. Якорные переходы могут сохранить отдельное плавное поведение. Вариант с одинаковой большой инерцией для любого `deltaY` отклонен: он делает тачпад неточным и вызывает типичное ощущение, что страница продолжает двигаться против пользователя. Стороннюю библиотеку следует добавлять только если компактная реализация не проходит сценарии тачпада и смены направления.

### Управлять размером кольца отдельным визуальным состоянием

Компонент курсора будет определять вход и выход указателя для явно подходящих интерактивных элементов и переключать класс или data-состояние кольца. Размер изменяется через `transform`/CSS transition совместно с координатным transform так, чтобы не вызывать перерасчет layout. Навигационные элементы и fragment-ссылки исключаются из выбора; coarse-pointer и reduced-motion сохраняют базовое поведение. Глобальное правило для всех `a` и `button` отклонено, потому что оно нарушает явное исключение навигации.

### Анимировать сам элемент навигации вместо кольца курсора

Для элементов шапки, меню, переключателя языка и внутренних навигационных ссылок кольцо остается базового размера. Hover-состояние задается самому элементу через существующие проектные паттерны — изменение цвета, подчеркивание/линию, небольшой сдвиг или уже используемый переход. Сначала следует переиспользовать имеющиеся CSS transition и motion-токены, чтобы не вводить второй визуальный язык. Анимация не должна смещать соседние элементы, скрывать focus-visible состояние или быть обязательной для понимания действия.

### Не переносить hash при переключении локали

Ссылка языка должна вести только на pathname выбранной локали. Обработчик не дописывает текущий hash, а переход должен гарантировать верх страницы; при необходимости это закрепляется явным scroll-to-top после завершения клиентской навигации. Сохранение hash отклонено, поскольку продуктовый контракт требует возвращения наверх и именно устаревший fragment создает текущую регрессию.

### Проверять поведение в реальном браузере

Добавить Playwright-сценарии для серии дискретных wheel-импульсов, малых частых событий тачпада, быстрой смены направления и достижения границ документа. Отдельно проверить переключение языка сверху, после прокрутки и при оставшемся hash, изменение состояния курсора на разрешенных элементах, базовый размер кольца над навигацией и hover-анимацию самой навигации. Существующие визуальные снимки оставить для контроля общего вида; unit-проверок HTML недостаточно для позиции прокрутки и pointer hover.

## Risks / Trade-offs

- [Клиентский роутер может восстанавливать позицию прокрутки иначе в разных сценариях истории] → Проверить прямой переход, fragment URL и обе исходные позиции; при необходимости явно сбрасывать прокрутку после смены pathname.
- [Селектор кликабельных элементов со временем может захватывать новую навигацию] → Использовать явный критерий/маркер для ненавигационных интерактивных элементов либо централизованное исключение `header`, `nav` и fragment-ссылок, закрепленное тестом.
- [Одновременные transform для позиции и масштаба могут перезаписывать друг друга] → Разнести позиционирование и масштабирование между оберткой/внутренним элементом или собрать оба преобразования в одном управляемом значении.
- [Hover-анимация может мешать пользователям с чувствительностью к движению] → Отключать переход масштаба и интерактивное состояние при `prefers-reduced-motion: reduce`.
- [Перехват wheel может сделать тачпад «ватным» или сломать вложенную прокрутку] → Не усиливать пиксельные delta, применять адаптивное сглаживание, быстро гасить противоположную инерцию и пропускать события вложенных прокручиваемых областей.
- [Два механизма smooth scroll могут складывать задержку] → Не применять CSS smooth behavior к покадровым обновлениям контроллера и отдельно проверить якорные переходы.
- [Программная, клавиатурная или восстановленная браузером позиция может рассинхронизировать цель] → Пересинхронизировать контроллер с фактическим `scrollY` перед новым жестом и при релевантных событиях навигации/изменения размера.

## Migration Plan

Изменение не требует миграции данных или конфигурации. Оно выпускается вместе с обновленными браузерными тестами; откат состоит в отключении контроллера wheel-прокрутки и возврате обработчика переключателя языка и hover-состояния курсора к предыдущей реализации.
