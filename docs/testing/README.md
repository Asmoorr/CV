# Тестирование

## Уровни проверки

Проект использует несколько взаимодополняющих проверок:

| Проверка | Команда | Что обнаруживает |
| --- | --- | --- |
| Типы | `npm run typecheck` | Несоответствия TypeScript-типам |
| Стиль кода | `npm run lint` | Ошибки ESLint и предупреждения Next.js |
| Контент | `npm test` | Нарушения структуры и обязательных правил данных |
| Production-сборка | `npm run build` | Ошибки сборки и серверного рендеринга |
| SEO production contract | `npm run test:seo` | Redirect, initial HTML metadata, canonical/hreflang, JSON-LD, robots, sitemap и social images после сборки |
| Внешний вид | `npm run test:visual` | Нежелательные изменения страниц на разных экранах |

Перед отправкой изменений рекомендуется выполнить все пять проверок.

## Тесты контента

Команда:

```bash
npm test
```

Vitest запускает `tests/content.test.ts`. Тесты проверяют, что:

- русская и английская версии имеют одинаковую верхнеуровневую структуру;
- элементы хронологии и проектов совпадают между языками по идентификаторам;
- у проектов согласованы ссылка и подпись ссылки;
- прямые контактные данные имеют ожидаемый формат;
- в опубликованных данных не осталось редакционных заглушек.

При добавлении нового обязательного правила для контента его следует закрепить отдельным тестом.

## Визуальные тесты

Playwright сравнивает полные страницы `/ru` и `/en` с эталонными PNG. Проверяются три конфигурации:

- desktop — 1440 × 1000;
- tablet — 768 × 1024;
- mobile — 320 × 800.

Перед первым запуском установите Chromium, соответствующий версии Playwright:

```bash
npx playwright install chromium
```

Запустите сравнение:

```bash
npm run test:visual
```

Команда предварительно выполняет production-сборку, запускает standalone-сервер на `127.0.0.1:3100` и делает снимки в Chromium. Для стабильности тестов используются тёмная цветовая схема, отключённые анимации, фиксированный масштаб и режим уменьшенного движения.

Допустимая доля отличающихся пикселей задана в `playwright.config.ts` и составляет `0.001`. При ошибке actual-, expected- и diff-изображения, трассировка и HTML-отчёт сохраняются в `artifacts/playwright`.

Откройте отчёт:

```bash
npm run test:visual:report
```

## Обновление эталонных снимков

Обновляйте снимки только для намеренного и проверенного изменения дизайна:

```bash
npm run test:visual:update
npm run test:visual
```

После обновления просмотрите каждый PNG в `tests/visual/resume.visual.ts-snapshots` и убедитесь, что на обеих локалях корректны:

- расположение секций;
- переносы и отсутствие обрезанного текста;
- мобильная и планшетная компоновка;
- цвета, отступы и типографика;
- контактные данные и ссылки.

Не обновляйте эталоны только ради успешного результата теста. Обновление Playwright, Chromium или операционной системы может изменить рендеринг и потребовать отдельного осознанного пересоздания снимков.

## Рекомендуемый порядок проверки

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run test:seo
npm run test:visual
```

`npm run test:visual` уже включает сборку. Отдельный `npm run build` в полном цикле полезен как самостоятельная, легче диагностируемая проверка; при быстром локальном прогоне его можно не повторять.

## Добавление тестов

- Правила структуры данных добавляйте в `tests/content.test.ts`.
- Сценарии отображения добавляйте в `tests/visual` с суффиксом `.visual.ts`.
- Эталонные снимки храните рядом с визуальным тестом в каталоге `<имя-теста>-snapshots`.
- Генерируемые отчёты и результаты оставляйте в `artifacts/playwright`; они не являются эталонами.
