## Context

`Footer` сейчас является серверным компонентом с двумя строками композиции и не содержит элемента возврата наверх. В `Header` уже используется ссылка `href="#top"`, но в shell страницы нет явной точки с таким id. Глобальные стили уже задают `scroll-behavior: smooth`, `scroll-padding-top`, `prefers-reduced-motion` и видимый `:focus-visible`; `SmoothWheelScroll` перехватывает только wheel-события и должен оставаться независимым от программного возврата наверх.

## Goals / Non-Goals

**Goals:**

- Добавить одну выразительную, но компактную control-зону в footer.
- Сохранить существующую визуальную систему, Manrope, палитру и адаптивную сетку.
- Сделать действие работоспособным без сетевых запросов и безопасным при reduced motion.
- Связать кнопку с явной точкой `#top` и передать фокус на начальный доступный элемент после возврата.
- Проверить реальное поведение в браузере, а не только серверную разметку.

**Non-Goals:**

- Изменение contact-секции, sessionStorage-флага или footer-подписи.
- Добавление плавающей кнопки поверх viewport, scroll spy, scroll snapping или новой библиотеки анимации.
- Изменение существующего wheel-контроллера и поведения ссылок навигации, кроме добавления отсутствующей точки `#top`.

## Decisions

### Локализованный клиентский контрол для возврата и фокуса

Добавить небольшой `BackToTop`-компонент, который получает локализованное доступное имя из `FooterContent`. Визуально это простая стрелка вверх без видимой подписи и рамки; цвет области вокруг стрелки совпадает с фоном footer, а доступное имя остаётся доступным скринридерам. Обработчик использует `window.scrollTo` или переход к `#top`, выбирая `behavior: "smooth"` только при отсутствии reduced motion, затем переводит фокус на начальный элемент страницы с `preventScroll`.

Явная точка `#top` добавляется в существующий верхний shell страницы. Она не меняет layout, но исправляет также уже существующую ссылку бренда в Header. `main` остаётся целевым skip-link и логичным элементом для фокуса после возврата.

### Встроенная footer-композиция вместо fixed overlay

Кнопка размещается в footer через существующую grid/flex-композицию, чтобы она оставалась частью reading order на mobile и не перекрывала контент. Стрелка использует акцентный цвет проекта; hover/focus дают небольшой подъём через `transform`, не добавляя рамку и не меняя занимаемое место. На точных указателях можно добавить небольшой подъём через существующий `--motion-fast`; при reduced motion переходы отключаются глобальным контрактом.

### Локализация через контентную схему

В `FooterContent` добавляется поле для локализованного доступного имени кнопки с русским и английским значением. Видимая подпись не показывается; смысл действия остаётся доступным вспомогательным технологиям.

## Implementation Outline

1. Расширить `FooterContent` и оба локализованных footer-контента.
2. Добавить `#top` на верхний shell и передать кнопку в `Footer`.
3. Реализовать `BackToTop` и стили стрелки, focus и адаптивного размещения без видимой подписи и рамки.
4. Сохранить текущую информацию footer и проверить, что новая control-зона не вызывает overflow на `320px`.
5. Добавить component/Playwright проверки и обновить visual baselines только если итоговая композиция footer действительно меняет снимки.

## Risks / Trade-offs

- [Переход к anchor может конкурировать с wheel-контроллером] → Использовать программный `scrollTo` вне wheel-пути и синхронизировать контроллер через уже существующее событие `smooth-scroll:reset`, если это требуется фактическим поведением.
- [Фокус на странице может сам изменить прокрутку] → Сделать target начального элемента `tabIndex={-1}` и применять `focus({ preventScroll: true })` после запуска возврата.
- [Смысл кнопки может быть неясен без подписи] → Сохранить локализованное доступное имя, а стрелку оставить видимой и понятной в базовом состоянии.
- [Footer может стать тесным на mobile] → Не использовать абсолютное позиционирование; перенести control-зону в адаптивный поток и проверить 320px/768px/1440px.

## Verification

- Vitest: серверный HTML обеих локалей содержит кнопку с локализованным доступным именем, а существующие footer-данные сохраняются.
- Playwright: клик и Enter/Space из нижней части страницы возвращают `scrollY` к нулю; focus-visible присутствует; reduced motion не запускает продолжительный smooth-переход; кнопка видна и не вызывает горизонтальный overflow на desktop/tablet/mobile.
- Playwright/visual: hover/focus меняют положение стрелки без рамки и layout shift; проверяются `/ru` и `/en`.
