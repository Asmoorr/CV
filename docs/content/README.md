# Контент и локализация

## Где хранится контент

Тексты резюме отделены от React-компонентов и находятся в двух каталогах:

- `src/content/ru` — русская версия;
- `src/content/en` — английская версия.

Каждая смысловая часть вынесена в отдельный файл:

| Файл | Содержание |
| --- | --- |
| `navigation.ts` | Навигация, подписи меню и переключателя языка |
| `hero.ts` | Имя, роль, краткое описание и основные действия |
| `about.ts` | Рассказ о специалисте и ключевые факты |
| `timeline.ts` | Опыт, обучение и другие события хронологии |
| `projects.ts` | Проекты, вклад и технологии |
| `skills.ts` | Основные навыки и тематические группы |
| `contact.ts` | Контактные данные и подписи |
| `footer.ts` | Содержание нижней части страницы |
| `index.ts` | Сборка файлов локали в единый объект |

Общие типы находятся в `src/content/schema.ts`. Файл `src/content/index.ts` экспортирует обе локали, список поддерживаемых языков и функцию их проверки.

## Как изменить текст

1. Найдите нужную секцию в `src/content/ru`.
2. Внесите аналогичное по смыслу изменение в соответствующий файл `src/content/en`.
3. Сохраните существующие идентификаторы элементов, если это не новая сущность.
4. Выполните `npm test` и `npm run typecheck`.
5. Если изменилась длина или компоновка текста, запустите визуальные тесты.

Не добавляйте биографические строки непосредственно в компоненты из `src/components`: компоненты должны оставаться независимыми от конкретного языка и содержания.

## Согласованность локалей

Обе версии соответствуют типу `ResumeContent`. При изменении модели данных:

1. обновите типы в `src/content/schema.ts`;
2. заполните новое поле для `ru` и `en`;
3. передайте данные в нужный компонент;
4. при необходимости дополните проверки в `tests/content.test.ts`.

Идентификаторы элементов `timeline` и `projects` должны совпадать между языками и сохранять одинаковый порядок. Они обозначают одну и ту же сущность, а не переводимый текст.

Для проекта поля `href` и `linkLabel` используются вместе: либо присутствуют оба, либо отсутствуют оба. Проект без публичной ссылки допустим и отображается без действия перехода.

## Добавление элемента

Для нового события хронологии или проекта:

- придумайте стабильный короткий `id` на латинице;
- добавьте элемент с тем же `id` в обе локали;
- переведите смысл, а не структуру предложения слово в слово;
- проверьте ссылки и названия технологий;
- убедитесь, что порядок элементов совпадает.

## Добавление новой секции

1. Опишите данные секции отдельным типом в `src/content/schema.ts`.
2. Добавьте поле в `ResumeContent`.
3. Создайте одноимённые файлы в каталогах `ru` и `en`.
4. Экспортируйте данные из локальных `index.ts`.
5. Создайте компонент в `src/components/sections`.
6. Подключите компонент в `src/app/[locale]/page.tsx`.
7. Если секция входит в основную навигацию, добавьте её идентификатор и подписи в обе версии `navigation.ts`.
8. Дополните тесты и визуальные эталоны.

## Добавление языка

Текущая реализация явно рассчитана на `ru` и `en`. Для третьего языка потребуется изменить не только данные:

- расширить тип `Locale` и список `locales`;
- создать новый каталог в `src/content`;
- подключить его в `src/content/index.ts`;
- расширить проверку пути в `src/proxy.ts`;
- добавить язык в переключатель `Header`;
- обновить тесты контента и визуальные сценарии.

После этого проверьте метаданные, атрибут `lang`, корневое перенаправление и все размеры экрана.

## Редакционные правила

- Не публикуйте временные пометки и заглушки.
- Сохраняйте факты и даты согласованными между языками.
- Используйте полные публичные URL для внешних ссылок.
- Не помещайте секреты или закрытые контактные данные в исходный код.
- Проверяйте читаемость длинных формулировок на мобильном экране.
