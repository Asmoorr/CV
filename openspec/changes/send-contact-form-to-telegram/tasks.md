## 2. Реализовать и проверить серверный endpoint

- [ ] 2.1 Создать `POST /api/contact` с проверкой Content-Type, лимитом тела 16 KiB, обязательными строковыми полями, нормализацией и заданными пределами длины; проверить валидные и ошибочные payload unit-тестами.
- [ ] 2.2 Реализовать отправку plain-text сообщения через Telegram Bot API с `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, тайм-аутом, проверкой HTTP-ответа и JSON-поля `ok`; проверить успех, отказ, тайм-аут и отсутствие автоматического повтора замоканным `fetch`.
- [ ] 2.3 Возвращать стабильные JSON-коды и HTTP-статусы `200`, `400`, `413`, `415`, `429`, `502`, `503`, не включая в ответы данные формы или детали Telegram; проверить контракт ответов и отсутствие вызова Telegram при невалидных данных или отсутствующей конфигурации.
- [ ] 2.4 Убедиться, что обработчик не пишет поля формы, bot token или URL Bot API в логи; проверить журналы тестовых success/error сценариев на отсутствие персональных данных и секретов.
