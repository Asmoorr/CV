# Design

## Context

См. [proposal.md](proposal.md) для мотивации изменения и [spec delta](specs/scroll-guidance-and-reveal/spec.md) для внешнего поведения. Сейчас `Hero` является серверным компонентом с клиентским `HeroField`, а входная анимация управляется атрибутом `html[data-entry-state]`. Плавная прокрутка уже централизована в root-интеграции Lenis; отдельный компонент `Timeline` использует одноразовый `IntersectionObserver`, что подходит для reveal, но не для обратимого scroll-linked состояния.

Hero в настоящее время ограничен одним viewport, а его `.content` уже анимируется через `opacity` и `transform` во время входа. Поэтому новый эффект должен иметь собственный sticky-stage и применять transform только к вложенным словам, не перезаписывая transform внешнего `.content`.

## Goals / Non-Goals

**Goals:**

- Создать обратимое состояние Hero, где слова приближаются к зрителю, увеличиваются и исчезают при прокрутке вниз. Обе CTA, статус, город и два круга анимируются целиком.
- Использовать один источник прогресса — существующий Lenis — без GSAP, второго wheel-handler или второго animation loop.
- Сохранить SSR-разметку, доступное имя заголовков, нормальный no-JavaScript fallback и естественный порядок чтения.
- Отделить word-level motion от интерактивных CTA, canvas-поля и entry transition.
- Обеспечить предсказуемый детерминированный результат на каждом рендере и адаптивные параметры для мобильных экранов.

**Non-Goals:**

- Замена Lenis, entry overlay, `HeroField` или существующего reveal Timeline.
- Добавление GSAP, ScrollTrigger, Framer Motion или иной animation-экосистемы.
- Разбиение CTA, ссылок и служебных метаданных на отдельные анимируемые слова.
- Удаление текста из DOM, изменение локализованного контента или добавление серверного API.

## Decisions

### 1. Использовать scroll-range со sticky-stage

Увеличить структурную высоту Hero примерно до двух viewport-высот и разместить его визуальное содержимое во внутреннем sticky-stage высотой один viewport. Прогресс рассчитывается по доле пройденного диапазона Hero:

```text
progress = clamp(
  -hero.getBoundingClientRect().top
  / (hero.offsetHeight - viewportHeight),
  0,
  1
)
```

При `progress = 0` слова находятся в обычной позиции, а при `progress = 1` достигают конечного состояния рассеивания. Sticky-stage удерживает содержимое в viewport, пока прогресс изменяется. Clipping переносится с структурного Hero на отдельный visual-layer либо заменяется способом, который не ломает `position: sticky`; это также удерживает `HeroField` в размере viewport вместо растягивания canvas на всю увеличенную секцию.

Альтернатива — привязать анимацию к `IntersectionObserver`. Она отклонена: observer хорошо определяет вход/выход, но не даёт непрерывного обратимого прогресса при остановке и смене направления.

### 2. Подключить `useLenis` как единственный scroll callback

Новый локальный клиентский компонент регистрирует callback через `useLenis`. Callback получает актуальное движение, вычисляет progress по DOM-геометрии Hero и обновляет refs слов императивно. React state не используется на каждом кадре, чтобы прокрутка не вызывала перерисовку всего дерева Hero.

Lenis уже владеет своим `autoRaf`, поэтому компонент не создаёт собственный `requestAnimationFrame`. Callback должен быть снят при размонтировании через контракт `useLenis`; wheel/touch-ввод и target scroll не перехватываются.

### 3. Рендерить локализованный текст как семантические inline-block words

`Hero.tsx` остаётся серверным, но передаёт строки в небольшой клиентский word-level компонент. Компонент рендерит слова внутри существующего семантического `h1`/`p`, сохраняя пробелы и естественный порядок. Для интерактивных ссылок и CTA используется обычная разметка вне word-level слоя.

Не добавлять дублирующий visually-hidden текст без необходимости: видимые inline-элементы остаются частью доступного имени, а отсутствие JavaScript показывает тот же текст без начального скрытия. Пунктуация и пробелы должны сохраняться при токенизации, чтобы локали не меняли смысл или переносы строк.

### 4. Использовать детерминированные профили ретракции

Для каждого слова или целого элемента вычисляется детерминированный profile. Он содержит ограниченные `xPercent`, `yPercent`, положительный `z` (360–600px) и `rotateX`. Общий hook применяется и к словам, и к шести дополнительным элементам.

Прогресс преобразуется в параметры конечного состояния:

```text
opacity: 1 -> 0
x/y:     0 -> profile offset
z:       0 -> positive profile depth
rotateX: 0 -> profile rotation
```

Параметры интерполируются с нелинейностью и stagger-окном. Родитель слов получает `perspective`; целые элементы используют `perspective()` в transform. На мобильных глубина умножается на 0.7, горизонтальное смещение — на 0.5. Конечная глубина остаётся меньше перспективы, чтобы элементы не пересекали плоскость камеры.

По уточнению пользователя отрицательный Z заменён положительным: элементы вылетают вперёд, как в референсе.

### 5. Развести entry transition, text dissolve и действия

Внешний `.content` сохраняет текущую `hero-in`-анимацию, управляемую `data-entry-state`. Word-level transforms применяются только к потомкам текстовых блоков после разблокировки основного сайта; во время `loading`, `ready` и `opening` entry overlay эффект удерживает исходное состояние.

Приветствие, имя, роль и summary получают word-level effect. CTA, статус, город и каждый круг получают тот же эффект целиком. Семантика ссылок и порядок фокуса сохраняются. При `:focus-visible` CTA восстанавливает opacity и transform; полностью исчезнувшие ссылки отключают pointer events. При reduced motion все элементы видимы.

### 6. Сохранить reduced-motion и деградацию

При `prefers-reduced-motion: reduce` компонент не применяет perspective, translateZ, rotateX или поэтапное уменьшение opacity; содержательный текст остаётся видимым. При отключённом JavaScript начальное CSS-состояние также должно быть полностью читаемым.

Слушатель изменения media query нужен, если пользователь меняет настройку движения во время открытой страницы. При переходе в reduced-motion состояние должно немедленно вернуться к нейтральным transform/opacity, без ожидания следующей прокрутки.

### 7. Проверять motion на наблюдаемом поведении

Добавить browser-проверки для верхней, промежуточной и конечной позиции Hero, обратной прокрутки, reduced-motion, entry overlay и отсутствия горизонтального overflow. Визуальные snapshots должны фиксировать не конкретные случайные координаты, а стабильные детерминированные состояния профиля на RU/EN и основных viewport-размерах.

## Risks / Trade-offs

- **[Risk]** `overflow: hidden` на текущем Hero может сделать sticky-stage неработоспособным или обрезать рассеянные слова. → **Mitigation:** отделить clipping visual-layer от структурного scroll-container и проверить sticky на desktop/mobile.
- **[Risk]** Увеличение Hero до двух viewport-высот замедлит переход к следующей секции. → **Mitigation:** начать с диапазона около 100svh дополнительного scroll-space и откалибровать длительность по визуальным snapshots, не добавляя snap.
- **[Risk]** Прямое обновление многих inline-стилей может вызвать лишнюю работу layout/paint. → **Mitigation:** изменять только transform/opacity, применять `will-change` к активным словам, не трогать размеры и использовать один Lenis callback.
- **[Risk]** Положительный Z может чрезмерно увеличивать элементы на мобильных устройствах. → **Mitigation:** ограничить глубину ниже перспективы, уменьшить мобильные смещения и проверить визуальные снимки.
- **[Risk]** Entry animation и scroll dissolve могут одновременно писать opacity/transform. → **Mitigation:** оставить entry transform на внешнем content-wrapper, а scroll transform — только на словах; запускать progress после разрешённого entry state.
- **[Risk]** Семантические inline-block элементы могут изменить переносы строк между локалями. → **Mitigation:** сохранять пробелы, не использовать фиксированную ширину слов, проверить RU/EN и мобильные ширины.

## Migration Plan

Изменение не требует миграции данных или новых зависимостей. Сначала добавить word-level слой и sticky-stage за feature-ready CSS/JS fallback, затем подключить Lenis progress, после чего обновить визуальные и поведенческие проверки. Для отката удалить новый клиентский компонент и вернуть Hero к текущей `min-height: 100svh`/`hero-in`-композиции; существующие `HeroField`, entry overlay и Lenis остаются без изменений.
