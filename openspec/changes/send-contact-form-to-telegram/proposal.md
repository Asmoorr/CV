# Proposal

## Why

Контактная форма из отдельного изменения `add-contact-form` отправляет данные на `/api/contact`, но их доставка требует серверной обработки. Endpoint должен безопасно принимать сообщение и пересылать его владельцу сайта через Telegram, сообщая посетителю об успехе только после подтверждения доставки.

## What Changes

- Добавить публичный `POST /api/contact` для существующей формы с контрактом полей `name`, `email` и `message`.
- Проверять тип, размер и содержимое запроса на сервере до обращения к Telegram; ограничивать частоту обращений и объём доставляемого текста.
- Пересылать проверенные данные одним сообщением через Telegram Bot API в единственный чат, заданный серверной конфигурацией.
- Хранить токен Telegram и ID целевого чата только в серверных переменных окружения; не возвращать внутренние ошибки и секреты клиенту.
- Возвращать успешный результат только после подтверждённого ответа Telegram; при временном сбое позволять форме сохранить введённые значения и показать возможность повторить отправку.
- Не сохранять сообщения в базе данных и не создавать отдельный постоянно работающий Telegram-сервис.
- Заменить существующий локальный сценарий «доставка не подключена» на фактическую отправку; визуальный дизайн формы и её поля остаются вне этого изменения.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `interactive-contact-and-footer`: заменить требование frontend-only поведения на контракт серверной доставки формы в настроенный Telegram-чат и определённые результаты/ошибки отправки.

## Impact

- Новый Next.js Route Handler `src/app/api/contact/route.ts` и, при необходимости, небольшая серверная функция отправки в Telegram.
- Интеграционный контракт формы с endpoint; интерфейс и локализованные подписи формы не перерабатываются.
- Серверная конфигурация `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` для Vercel Production и Preview; правила ограничения частоты для endpoint.
- Проверки входных данных, HTTP-статусов, доставки/ошибок Telegram и отсутствия утечки секретов или персонального текста в логах.
- Фронтенд-контракт принадлежит `openspec/changes/add-contact-form`; перед совместным применением нужно согласовать коды ответов и убрать дублирование задач подключения формы.
- Документация репозитория пока описывает production через Docker и VPS. Она расходится с указанным пользователем deployment на Vercel; выбранное здесь решение использует стандартный Next.js Route Handler и серверные переменные окружения.
