# Proposal

## Why

Hero должен постепенно разбираться на слова, вылетающие вперёд к зрителю через положительный Z и растворяющиеся, как в референсе. По уточнению пользователя в эффект включены обе CTA, статус, город и два декоративных круга.

## What Changes

- Добавить для Hero отдельный scroll-linked exit-эффект с расширенной областью прокрутки и sticky-stage, чтобы текст оставался в viewport во время рассеивания.
- Разбивать локализованные greeting, имя, роль и summary на отдельные слова с детерминированными профилями смещения.
- При прокрутке вниз изменять `opacity`, X/Y, положительный Z и `rotateX`, создавая ощущение приближения и растворения; при прокрутке вверх возвращать все элементы в исходное состояние.
- Синхронизировать прогресс эффекта с существующим Lenis через его scroll callback, не добавляя GSAP, отдельный wheel-listener или второй `requestAnimationFrame`-loop.
- Анимировать каждую CTA, статус, город и каждый круг целиком тем же эффектом. Кнопки при клавиатурном фокусе возвращаются в видимое исходное положение; полностью исчезнувшие кнопки не перехватывают указатель.
- Сохранить исходный текст в серверной разметке, естественный порядок чтения и рабочую версию без JavaScript.
- При `prefers-reduced-motion: reduce` отключать перемещение и 3D-рассеивание, оставляя Hero-текст видимым и доступным.
- Ограничить глубину и смещения на узких экранах, исключить горизонтальный overflow и проверить визуальные состояния в нескольких точках прогресса.

## Capabilities

### New Capabilities

Нет. Поведение является расширением существующей motion/reveal-системы Hero.

### Modified Capabilities

- `scroll-guidance-and-reveal`: добавить обратимый scroll-linked exit Hero и уточнить, что он не заменяет одноразовый reveal остальных секций, не скрывает семантический текст и отключается при reduced motion.

## Impact

- Затрагиваются `src/components/sections/Hero.tsx`, `src/components/sections/Hero.module.css` и новый локальный клиентский компонент для word-level scroll-progress.
- Потребуется использовать публичный `useLenis` API из существующей интеграции `src/components/SmoothWheelScroll.tsx`; новые зависимости не добавляются.
- Понадобятся обновления спецификации и Playwright-визуальные/поведенческие проверки для верхней, промежуточной и конечной точек Hero на RU/EN, desktop и mobile.
- Изменяется только поведение Hero при прокрутке; entry overlay, canvas-поле, CTA-навигация, остальные секции и общий wheel-контракт остаются в текущем scope.
