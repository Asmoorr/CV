## Why

Публикация текущей версии сайта на удалённый сервер выполняется вручную, поэтому содержимое `main` и production могут расходиться, а процесс обновления и отката остаётся непроверяемым. Нужен воспроизводимый автоматический deployment после каждого успешного изменения `main`, сохраняющий существующую схему Nginx → приложение на `127.0.0.1:3000`.

## What Changes

- Добавить GitHub Actions workflow, который при push в `main` выполняет обязательные проверки, собирает неизменяемый Docker-образ и публикует его в GitHub Container Registry.
- Добавить управляемую Docker Compose-конфигурацию production-сервиса, привязывающую приложение только к `127.0.0.1:3000` для работы за существующим Nginx.
- Автоматизировать доставку на сервер по SSH: загрузку образа конкретного commit SHA, безопасную замену контейнера и проверку доступности сайта через HTTPS.
- Не считать deployment успешным, пока новый контейнер и публичный endpoint не прошли health check; предусмотреть документированный откат на предыдущий образ.
- Описать первоначальную настройку сервера, GitHub Environments/Secrets, минимальные права deploy-пользователя и операционные действия без хранения секретов в репозитории.
- Сохранить текущую TLS-терминацию и HTTP→HTTPS redirect в Nginx; изменение домена и сертификатов в scope не входит.

## Capabilities

### New Capabilities

- `continuous-production-deployment`: Автоматическая проверяемая доставка каждого успешного commit из `main` в production через GitHub Actions, GHCR, SSH и Docker Compose с контролем готовности и возможностью отката.

### Modified Capabilities

- Нет: опубликованных основных OpenSpec-спецификаций в проекте пока нет; существующий change `redesign-cv-nextjs` уже описывает сборку Docker-образа, но не автоматическую доставку на сервер.

## Impact

- Репозиторий: новый workflow в `.github/workflows`, production Compose-конфигурация, deploy-скрипт/команды и документация эксплуатации.
- GitHub: Container Registry, защищённое environment `production`, Actions secrets/variables и минимальные permissions для workflow.
- Сервер: отдельный deploy-пользователь, каталог deployment, доступ к Docker и GHCR, сохранение текущего Nginx-конфига и Certbot-сертификатов.
- Runtime: порт приложения остаётся `3000`, но публикуется только на loopback-интерфейсе; публичный трафик продолжает принимать Nginx.
- Внешний API и пользовательские маршруты сайта не меняются. Кратковременный перерыв при замене одного контейнера допустим; zero-downtime deployment не входит в первоначальный scope.
