## Context

Сейчас проект состоит из одного `cv.html`, в котором смешаны разметка, стили, анимации, русский и английский тексты. Hero-секция визуально сильна; аудит нижних разделов выявил чрезмерные вертикальные интервалы, шаблонную сетку навыков, слабый контраст, повторение паттерна хронологии для единственной записи об образовании и фиктивную контактную форму. См. `proposal.md` и спецификации этой change.

## Goals / Non-Goals

**Goals:**

- создать самостоятельный Next.js App Router проект на React и TypeScript;
- сохранить узнаваемость hero, но дать нижним секциям более плотный ритм и собственную композицию;
- сделать профессиональную историю сканируемой за 30–60 секунд;
- отделить весь редактируемый текст от компонентов;
- обеспечить корректный desktop/mobile, keyboard focus и reduced motion;
- подготовить production Docker-образ и понятный запуск.

**Non-Goals:**

- CMS, административная панель и база данных;
- серверная отправка контактной формы;
- аналитика, cookie-баннер и внешние маркетинговые интеграции;
- удаление или переписывание исходного `cv.html` до приёмки новой версии;
- выдумывание метрик, ссылок и фактов, которых нет в исходном резюме.

## Decisions

### 1. Next.js App Router с преимущественно серверными компонентами

Страница строится на Next.js и TypeScript. Статические секции рендерятся на сервере; клиентскими остаются только переключатель языка, мобильная навигация и ограниченная интерактивная графика hero. Это сокращает JavaScript в браузере и сохраняет хорошую индексацию.

Альтернатива: полностью клиентское React-приложение. Отклонена, потому что резюме преимущественно статично и не требует SPA-состояния.

### 2. Локализация через типизированные контентные модули

Общая схема `ResumeContent` описывает обязательные поля. Русская и английская версии экспортируют объекты этого типа. Секции не импортируют произвольные строки напрямую: корневая страница выбирает локаль и передаёт соответствующий фрагмент данных.

Предпочтительная структура:

```text
src/
  app/
    [locale]/page.tsx
    layout.tsx
    globals.css
  components/
    sections/
    ui/
  content/
    schema.ts
    ru/
      navigation.ts
      hero.ts
      about.ts
      timeline.ts
      projects.ts
      skills.ts
      contact.ts
      footer.ts
    en/
      ...те же файлы
```

Альтернатива: единый крупный словарь i18n, как в `cv.html`. Отклонена: он неудобен для редактирования длинных записей и не обеспечивает содержательную типизацию.

### 3. Визуальная система «инженерный профиль»

Нижняя часть использует логику технического профиля: ясные связи между периодом, вкладом, результатом и стеком. Декоративные рамки и метки применяются только там, где кодируют структуру.

**Цветовые токены:**

- `Carbon` — `#0D0F10`, основной фон;
- `Graphite` — `#15191B`, локальные поверхности;
- `Steel` — `#A9B0B4`, вторичный текст с повышенным контрастом;
- `Paper` — `#F4F7F8`, основной текст;
- `Signal blue` — `#48C7F4`, ссылки, фокус, активное состояние;
- `Rule` — `#2A3033`, смысловые разделители.

**Типографика:** Manrope сохраняется как связь с hero и используется во всём интерфейсе. Вместо добавления шаблонного моноширинного шрифта различия создаются шириной колонки, весом, размером и табличными цифрами для дат. Текстовые строки ограничиваются примерно 68–72 символами.

**Композиция:** всё выравнивается по левой границе общей сетки. Hero остаётся центральной сценой, после него страница переходит в асимметричную 12-колоночную сетку.

```text
┌──────────────────────────────────────────────────────────┐
│ HERO: имя / роль / действия / атмосферная графика        │
└──────────────────────────────────────────────────────────┘
│ профиль 4 cols │ короткий рассказ 8 cols                 │
├────────────────┼─────────────────────────────────────────┤
│ периоды 3 cols │ единая карьерная лента 9 cols           │
├──────────────────────────────────────────────────────────┤
│ ИЗБРАННЫЕ ПРОЕКТЫ: одна широкая + одна компактная запись │
├──────────────────────────────────────────────────────────┤
│ основной стек крупно │ инструменты │ архитектура          │
├──────────────────────────────────────────────────────────┤
│ приглашение и статус │ email / телефон / GitHub           │
└──────────────────────────────────────────────────────────┘
```

Первоначально рассматривалась сетка карточек для всех разделов. После сверки с аудитом она исключена как слишком похожая на типовой SaaS-шаблон. Карточки допускаются только для проектов, потому что там действительно объединяют самостоятельные сущности.

### 4. Один выразительный приём ниже hero

Главный визуальный приём нижней части — непрерывная карьерная ось, которая соединяет работу и образование. Ghost-номера секций, бесконечная бегущая строка и повсеместные hover-трансформации удаляются. Это сохраняет энергию hero и делает основную часть спокойнее и профессиональнее.

### 5. Контакт без ложной отправки

Форма удаляется, пока нет реального сервиса отправки. Вместо неё используются `tel:`, `mailto:` и внешний URL GitHub. Email хранится обычной строкой, без Cloudflare-декодера. Для наиболее удобного действия допускается кнопка копирования email с честным подтверждением «Адрес скопирован».

### 6. Motion и курсор как улучшение, а не зависимость

Загрузка hero может иметь одну согласованную анимационную последовательность. Нижние секции не получают индивидуальные fade-up эффекты. Интерактивный курсор включается только при `(hover: hover) and (pointer: fine)`; стандартный курсор не отключается глобально. При reduced motion интерактивная сетка становится статичной.

### 7. Docker standalone output

Next.js настраивается на `output: "standalone"`. Multi-stage Dockerfile содержит dependency, build и минимальный runtime-слои. Runtime запускается непривилегированным пользователем, слушает `0.0.0.0:3000` и содержит только standalone-вывод, public-ресурсы и необходимые статические файлы.

Альтернатива: экспорт полностью статического HTML и nginx. Отклонена, чтобы не ограничивать маршрутизацию локалей и возможные будущие Next.js-возможности; при этом текущий дизайн остаётся совместимым со статическим рендерингом.

## Risks / Trade-offs

- [Недостаточно измеримых результатов в исходном тексте] → оставить явно отмеченные редакторские поля и не публиковать выдуманные цифры.
- [Неизвестен реальный email] → блокировать публичную ссылку до заполнения подтверждённого адреса.
- [Интерактивная hero-графика может ухудшить производительность] → ограничить плотность по размеру экрана, остановить вне viewport и предоставить статический reduced-motion режим.
- [Две локали увеличивают объём редактирования] → общая TypeScript-схема и проверка паритета на этапе сборки.
- [Standalone Docker-образ сложнее простого static export] → документировать сборку и добавить smoke-проверку контейнера.
- [Manrope загружается извне и может блокироваться] → использовать `next/font` с локальным включением шрифтовых файлов в сборку.

## Migration Plan

1. Создать Next.js-проект рядом с неизменённым `cv.html`.
2. Перенести и типизировать тексты; заполнить подтверждённые контакты и ссылки.
3. Реализовать структуру секций и визуальную систему, начиная с статичного responsive-макета.
4. Добавить ограниченную интерактивность hero и переключение локали.
5. Провести визуальную проверку desktop/mobile, keyboard и reduced motion.
6. Собрать standalone production-версию и проверить Docker-контейнер.
7. После приёмки переключить точку публикации на Next.js. При проблеме откат выполняется возвратом к публикации исходного `cv.html`.
