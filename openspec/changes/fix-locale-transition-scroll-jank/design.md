# Design

## Context

См. `proposal.md` и дельту `site-interactions`. Сейчас `[locale]/layout.tsx` является корневым layout и задаёт серверный `<html lang={locale}>`, шрифты, входной слой, Lenis и провайдер перехода. В проверенной версии Next.js переход `/ru` → `/en` заменяет DOM провайдера, входного контейнера и шапки, но не сам объект `document.body`. Атрибуты `<html>`, выставленные вручную, при этом могут быть перезаписаны. Поэтому состояние React или атрибут `<html>` не являются надёжной границей для анимации между локалями.

## Goals / Non-Goals

**Goals:**

- Сохранить серверный `lang`, статические маршруты и существующую модель входа при изменении механизма перехода.
- Сделать границу между скрытием старого DOM и показом нового независимой от размонтирования locale layout.
- Оставить полосу прокрутки и ширину страницы стабильными, пока Lenis остановлен.

**Non-Goals:**

- Сохранение позиции или открытой секции при переключении языка.
- Переработка анимаций секций, якорной навигации и настройки инерции Lenis.

## Decisions

### 1. Координировать переход вне заменяемого locale layout

Создать небольшой клиентский координатор одной текущей операции на уровне модуля и визуальный экран перехода, присоединяемый к `document.body` вне корня React. Текущий `LocaleTransitionProvider` запускает выход; после завершения скрытия координатор фиксирует начало страницы и вызывает `router.push`. Новый экземпляр провайдера читает ожидаемый pathname из координатора, дожидается появления новой локали и готовности прокрутки, затем открывает экран и завершает операцию. При отмене, ошибке или уходе на другой маршрут координатор освобождает экран и возвращает прокрутку. На жёсткой загрузке модульное состояние сбрасывается естественно.

Экран перекрывает и шапку, и основной контент, чтобы замена локализованного текста и DOM оставалась скрытой. Блокировка повторных кликов и `aria-busy` действуют до завершения входа новой страницы. Для reduced motion переход между состояниями выполняется без заметной анимации.

Альтернатива — перенести `<html>` и провайдер в `app/layout.tsx` выше `[locale]`. Она потребовала бы отдельного способа серверно выставлять корректный `lang` для каждой локали и могла бы изменить статическую генерацию. Для локальной проблемы это слишком большой риск. Один только CSS на нынешней `.surface` не помогает: её DOM и состояние провайдера заменяются при навигации.

### 2. Привязать смену позиции к фактическому завершению скрытия

Вместо независимых чисел 150 и 180 мс координатор ждёт завершения анимации экрана перехода (`transitionend` с защитным таймаутом), затем выполняет немедленный сброс позиции и навигацию. Перед открытием новой страницы он ещё раз фиксирует `scrollY = 0` после её монтирования. Никакая смена высоты русской и английской страницы не показывается пользователю в промежутке.

Альтернатива — увеличить первый таймер до 180 мс. Это устранило бы только ранний сброс прокрутки, но не размонтирование провайдера и разброс таймингов при замедлении браузера.

### 3. Оставить корневой scrollbar видимым при остановке Lenis

Сохранить `lenis.stop()` для отмены инерции, но переопределить его правило `overflow: clip` на корневом элементе именно во время locale transition и держать постоянный резерв под scrollbar (`scrollbar-gutter: stable` как страховку для браузеров с классической полосой). На время операции блокировать пользовательский ввод прокрутки, пока Lenis остановлен, не меняя ширину документа. Мобильное меню продолжает закрываться при выборе локали; его собственное `body.style.overflow` должно очищаться до раскрытия новой страницы. После навигации новый экземпляр Lenis запускается и проверяется фактическим вводом.

Альтернатива — отказаться от остановки Lenis. Тогда незавершённое движение может сдвинуть скрытую страницу и помешать точной установке начальной позиции.

### 4. Проверять переход по наблюдаемым фазам и геометрии

Расширить Playwright-сценарии для переключения сверху, после прокрутки и из мобильного меню. Проверять, что старое содержимое скрыто до изменения `scrollY`, новая локаль открывается только при `scrollY = 0`, переход завершается, scrollbar не исчезает, координаты шапки и контрольного элемента не меняются из-за временной блокировки, а колесо снова прокручивает страницу. Запускать сценарии также с reduced motion. Проверять фактическое поведение, а не сохранение конкретного экземпляра компонента.

## Risks / Trade-offs

- **[Risk]** Визуальный экран вне React может остаться после сбоя навигации. → Ограничить одну операцию, добавить защитный таймаут и централизованный `finally`/cleanup; проверить прерванный переход.
- **[Risk]** Переопределение `overflow` может позволить нативный ввод при остановленном Lenis. → На время операции перехватывать wheel/touch и проверять неподвижность страницы до контролируемого сброса.
- **[Risk]** У браузеров с overlay scrollbar измеряемая ширина не меняется даже при ошибке. → Проверять вычисленный `overflow` и видимость полосы отдельно от геометрии; дополнить прогоном в окружении с классическим scrollbar.
- **[Risk]** Одновременно смонтированные старый и новый Lenis кратко меняют классы на `<html>`. → Завершать открытие только после готовности нового контроллера и не использовать его CSS-класс как единственный сигнал готовности.

## Migration Plan

Изменение вводится без миграции данных и URL. После реализации проверить статическую сборку, `lang` обеих локалей, сценарий первого входа и браузерные тесты. Для отката вернуть текущий провайдер и CSS перехода вместе с прежней блокировкой Lenis; содержимое страниц и маршруты не меняются.
